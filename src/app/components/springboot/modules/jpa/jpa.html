20Módulo 4

JPA & Hibernate

JPA es la especificación Java para ORM; Hibernate es su implementación más popular. Spring Data JPA añade repositorios y una capa de abstracción encima.

Persistence Context
Cache de primer nivel gestionada por el EntityManager. Todas las entidades cargadas en la misma transacción son idénticas (misma referencia). Los cambios se sincronizan al hacer flush.
N+1 Problem
Cargar 1 entidad + N consultas para sus relaciones LAZY. Solución: JOIN FETCH en JPQL, @EntityGraph, o proyecciones DTO con una sola query.
Niveles de Caché
1er nivel: per-session (gratis, siempre activo). 2do nivel: cross-session compartida, requiere configuración (EHCache, Caffeine). Reduce queries a BD para datos que no cambian frecuentemente.
Estados de Entidad
Transient: nuevo, no en BD ni en contexto. Managed: en contexto, cambios detectados. Detached: fue managed, ya no. Removed: marcado para eliminar.
El problema N+1 es la causa más común de problemas de rendimiento en apps JPA. Identifícalo con spring.jpa.show-sql=true o Hibernate statistics.
21Módulo 4

@Entity & @Table

Las entidades JPA son clases Java que se mapean a tablas en la base de datos. La configuración se hace con anotaciones.

@Entity
@Table(name = "productos")
public class Producto {{ '{' }}
  @Id
  @GeneratedValue(strategy = GenerationType.IDENTITY)
  private Long id;
  @Column(name = "nombre", nullable = false, length = 100)
  private String nombre;
  @Embedded
  private Direccion direccion;
{{ '}' }}
GenerationType.IDENTITY
La BD genera el ID (AUTO_INCREMENT). Sencillo pero no optimizable en inserts por lote (batch) ya que Hibernate no puede predecir el ID.
GenerationType.SEQUENCE
Usa una secuencia de BD. Permite a Hibernate obtener IDs por adelantado (allocationSize), habilitando batch inserts eficientes.
GenerationType.UUID
Java 21+: @GeneratedValue(strategy = GenerationType.UUID). Genera un UUID v4 sin consultar la BD. Ideal para sistemas distribuidos.

CrudRepository & JpaRepository

Spring Data JPA genera implementaciones automáticas a partir del nombre del método, eliminando el código CRUD repetitivo.

public interface ProductoRepository extends JpaRepository<Producto, Long> {{ '{' }}
  List<Producto> findByNombreContainingIgnoreCase(String nombre);
  Optional<Producto> findByIdAndActivoTrue(Long id);
  boolean existsByNombre(String nombre);
  long countByActivo(boolean activo);
{{ '}' }}
JpaRepository extiende PagingAndSortingRepository que extiende CrudRepository. Añade: flush(), saveAndFlush(), deleteAllInBatch() y soporte para paginación.
23Módulo 4

JPQL & @Query

JPQL opera sobre entidades y sus campos Java, no sobre tablas SQL. @Query permite escribir JPQL o SQL nativo en el repositorio.

@Query("SELECT p FROM Producto p WHERE p.precio BETWEEN :min AND :max ORDER BY p.precio")
List<Producto> findByRangoPrecio(@Param("min") BigDecimal min, @Param("max") BigDecimal max);
@Modifying
@Transactional
@Query("UPDATE Producto p SET p.precio = p.precio * :factor WHERE p.categoria = :cat")
int actualizarPreciosPorCategoria(@Param("factor") BigDecimal factor, @Param("cat") String cat);
@Modifying requiere @Transactional. Añade clearAutomatically=true para limpiar el contexto de persistencia después de la actualización masiva.
24Módulo 4

Relaciones JPA

Las relaciones entre entidades se mapean con @OneToMany, @ManyToOne, @ManyToMany. La gestión del FetchType es crítica para el rendimiento.

FetchType.EAGER (evitar)
Carga SIEMPRE la colección
Queries automáticas e inesperadas
N+1 problem garantizado
@ManyToOne es EAGER por defecto
FetchType.LAZY (preferir)
Carga solo cuando se accede
Control total sobre las queries
Requiere transacción activa
@OneToMany es LAZY por defecto
@OneToMany(mappedBy = "pedido", cascade = CascadeType.ALL, orphanRemoval = true)
private List<LineaPedido> lineas = new ArrayList<>();
Usa Set en lugar de List para @ManyToMany. Hibernate usa una query más eficiente para gestionar la tabla intermedia con Sets.
25Módulo 4

Pagination & Sorting

Spring Data JPA integra paginación y ordenación mediante Pageable y Page<T> sin código adicional.

@GetMapping
public Page<Producto> listar(@PageableDefault(size = 20, sort = "nombre") Pageable pageable) {{ '{' }}
  return repo.findAll(pageable);
{{ '}' }}
// GET /productos?page=0&size=10&sort=precio,desc
Page<T>
Incluye los datos, número de página, total de elementos y total de páginas. Ejecuta dos queries: una para los datos y otra COUNT.
Slice<T>
Solo sabe si hay una página siguiente. Sin COUNT query. Ideal para scroll infinito cuando no necesitas el total.
26Módulo 4

@Transactional

Las transacciones garantizan atomicidad (ACID). Spring gestiona transacciones declarativamente con @Transactional, sin código boilerplate.

REQUIRED (defecto)
Usa la transacción existente o crea una nueva si no hay. El 95% de los casos.
REQUIRES_NEW
Suspende la transacción actual y crea una nueva independiente. Útil para auditoría o logs que deben persistir aunque la tx principal falle.
readOnly=true
Optimización para queries de solo lectura: deshabilita dirty checking de Hibernate, puede usar réplica de lectura en algunos drivers.
Self-invocation Problem
Llamar un método @Transactional desde el mismo objeto (this.metodo()) no activa la transacción porque Spring no intercepta llamadas internas al proxy.
@Transactional no funciona en métodos privados ni en llamadas directas dentro de la misma clase. Spring AOP solo intercepta llamadas externas al proxy.
