26 Módulo 5 · Spring Security Spring Security Intro
FilterChain · SecurityContext · Authentication · AuthenticationProvider
FilterChain
Spring Security se integra como una cadena de filtros Servlet. Cada request pasa por SecurityFilterChain antes de llegar al controlador. Los filtros se ejecutan en orden y pueden cortar la cadena si la autenticación falla.
SecurityContext
SecurityContextHolder almacena el contexto de seguridad del thread actual (estrategia ThreadLocal por defecto). Contiene el objeto Authentication con la información del usuario autenticado.
Authentication Object
Interfaz que encapsula: principal (identidad del usuario), credentials (contraseña u otros datos), authorities (roles/permisos) y el flag isAuthenticated.
Principal
Representa la identidad autenticada. Normalmente es un objeto UserDetails. Se puede obtener via SecurityContextHolder.getContext().getAuthentication().getPrincipal().
AuthenticationProvider
Responsable de verificar las credenciales. DaoAuthenticationProvider usa un UserDetailsService y un PasswordEncoder. Puedes implementar providers personalizados para LDAP, OAuth, JWT, etc.
Flujo básico: Request → DelegatingFilterProxy → SecurityFilterChain → AuthenticationManager → AuthenticationProvider → UserDetailsService → SecurityContext
// Obtener el usuario autenticado desde cualquier parte
Authentication auth = SecurityContextHolder.getContext().getAuthentication();
String username = auth.getName();
Object principal = auth.getPrincipal();
Collection<? extends GrantedAuthority> authorities = auth.getAuthorities();
27 Módulo 5 · Spring Security Configuración básica
SecurityFilterChain · permitAll · CSRF · HttpSecurity DSL · formLogin vs httpBasic
SecurityFilterChain @Bean
Desde Spring Security 5.7+ se configura declarando un @Bean de tipo SecurityFilterChain. Se reemplaza la extensión de WebSecurityConfigurerAdapter (deprecada). El método recibe un HttpSecurity.
permitAll / authenticated
permitAll() permite el acceso sin autenticación. authenticated() exige que el usuario esté autenticado. hasRole("ADMIN") restringe a un rol. Se configuran con authorizeHttpRequests().
CSRF
Cross-Site Request Forgery. Activado por defecto para formularios HTML. Se puede deshabilitar cuando la API es stateless y usa tokens (JWT/Bearer), ya que no hay cookies de sesión que explotar.
formLogin vs httpBasic
formLogin(): redirige a una página de login HTML (para aplicaciones web tradicionales). httpBasic(): envía credenciales en el header Authorization codificadas en Base64 (para APIs/servicios).
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {{ '{' }}
  http
    .authorizeHttpRequests(auth -> auth
      .requestMatchers("/public/**").permitAll()
      .requestMatchers("/admin/**").hasRole("ADMIN")
      .anyRequest().authenticated()
    )
    .csrf(csrf -> csrf.disable()) // API stateless
    .httpBasic(Customizer.withDefaults());
  return http.build();
{{ '}' }}
No deshabilites CSRF en aplicaciones con sesión y cookies. Solo es seguro hacerlo en APIs REST stateless que usan tokens Bearer.
28 Módulo 5 · Spring Security JWT Authentication
Estructura JWT · JwtEncoder/JwtDecoder · Bearer flow · Stateless · Secret vs RSA
Estructura JWT
Formato: header.payload.signature. Header: algoritmo y tipo. Payload: claims (sub, iat, exp, roles). Signature: HMAC o RSA sobre header+payload. Los claims son públicos — no almacenar datos sensibles sin cifrado.
JwtEncoder / JwtDecoder
JwtEncoder genera tokens firmados a partir de JwsHeader y JwtClaimsSet. JwtDecoder valida y parsea el token. Spring Security los provee con NimbusJwtEncoder/Decoder.
Bearer Token Flow
1. Cliente envía credenciales → 2. Servidor genera JWT → 3. Cliente guarda el token → 4. Cliente envía Authorization: Bearer <token> en cada request → 5. Servidor valida y extrae el usuario.
Stateless Session
Con JWT la sesión es stateless: el servidor no guarda estado. Se configura con sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS)). Mejora la escalabilidad horizontal.
Secret vs RSA Keys
HMAC/Secret (HS256): clave simétrica compartida, más simple. RSA (RS256): par público/privado, el servidor firma con la privada y los clientes verifican con la pública. RSA es preferido en producción.
// Generar JWT con JwtEncoder
JwtClaimsSet claims = JwtClaimsSet.builder()
  .issuer("self")
  .issuedAt(Instant.now())
  .expiresAt(Instant.now().plus(1, ChronoUnit.HOURS))
  .subject(username)
  .claim("roles", roles)
  .build();
String token = jwtEncoder.encode(JwtEncoderParameters.from(claims)).getTokenValue();
Un JWT expirado no puede ser revocado sin una lista negra (blocklist). Para revocar tokens antes de expirar, implementa una blocklist con Redis o usa tokens de corta duración con refresh tokens.
29 Módulo 5 · Spring Security SecurityFilterChain — Filtros personalizados
OncePerRequestFilter · addFilterBefore/After · UsernamePasswordAuthenticationFilter · ExceptionTranslationFilter
OncePerRequestFilter
Clase base para filtros personalizados que garantiza que se ejecuten exactamente una vez por request, incluso en forward/include internos. Implementa doFilterInternal(request, response, chain).
addFilterBefore / addFilterAfter
Posiciona tu filtro en la cadena relativo a un filtro existente. addFilterBefore(myFilter, UsernamePasswordAuthenticationFilter.class): ejecuta antes. addFilterAt: reemplaza en esa posición.
UsernamePasswordAuthenticationFilter
Filtro estándar de Spring Security para autenticación por formulario. Intercepta POST en /login y extrae username y password. Se puede personalizar o reemplazar con un filtro JWT.
ExceptionTranslationFilter
Captura excepciones de seguridad: AuthenticationException → redirige a login (401). AccessDeniedException → devuelve 403. Es el puente entre las excepciones de Spring Security y las respuestas HTTP.

30 Módulo 5 · Spring Security Method Security
@EnableMethodSecurity · @PreAuthorize · @PostAuthorize · SpEL · @Secured
@EnableMethodSecurity
Anotación de clase de configuración que habilita la seguridad a nivel de método. Reemplaza a @EnableGlobalMethodSecurity (deprecada en Spring Security 5.6). Activa prePostEnabled=true por defecto.
@PreAuthorize
Evalúa una expresión SpEL antes de ejecutar el método. Lanza AccessDeniedException si falla. Ejemplo: @PreAuthorize("hasRole('ADMIN')") o @PreAuthorize("#username == authentication.name").
@PostAuthorize
Evalúa una expresión SpEL después de ejecutar el método, con acceso al valor de retorno via returnObject. Útil para verificar que el recurso pertenece al usuario actual. El método ya se ejecutó.
SpEL Expressions
hasRole('ADMIN'), hasAuthority('READ'), hasAnyRole(...), isAuthenticated(), isAnonymous(), authentication.name, #param (parámetro del método), returnObject.
@Secured
Alternativa más simple que no usa SpEL. Acepta roles directamente: @Secured({{ '{' }}"ROLE_ADMIN", "ROLE_MOD"{{ '}' }}). Menos expresivo que @PreAuthorize. Requiere securedEnabled=true en @EnableMethodSecurity.
Method Security
@PreAuthorize("hasRole('ADMIN')")
public void deleteUser(Long id) {{ '{' }} ... {{ '}' }}
URL Security
.requestMatchers("/admin/**")
  .hasRole("ADMIN")
Method security y URL security pueden coexistir. URL security filtra a nivel de routing (más rápido), Method security es más granular y puede usarse en cualquier @Service o @Repository, no solo en controladores.

31 Módulo 5 · Spring Security OAuth2 Basics
Authorization Code · Resource Server · Client Credentials · Scopes · oauth2-resource-server
Authorization Code Flow
Flujo principal de OAuth2 para aplicaciones web: 1. App redirige a Authorization Server. 2. Usuario autentica y autoriza. 3. AS devuelve authorization code. 4. App intercambia el code por access token (server-to-server).
Resource Server
Servidor que protege los recursos y valida tokens. Con Spring Boot se habilita con spring-security-oauth2-resource-server. Configura oauth2ResourceServer(o -> o.jwt(...)) para aceptar Bearer tokens JWT.
Client Credentials
Flujo para comunicación machine-to-machine sin usuario. El cliente (servicio) autentica directamente con sus propias credenciales y obtiene un token. Ideal para microservicios, cron jobs y daemons.
Scopes
Definen el alcance de acceso del token. Ejemplos: read, write, openid, profile. Los scopes limitan qué puede hacer el cliente, a diferencia de los roles que definen qué puede hacer el usuario.
oauth2-resource-server
Dependencia spring-boot-starter-oauth2-resource-server incluye soporte para validar JWT y tokens opacos (introspección). Configura automáticamente JwtDecoder con la propiedad spring.security.oauth2.resourceserver.jwt.issuer-uri.
# application.yml — Resource Server con JWT
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://auth.example.com
// SecurityFilterChain para Resource Server
http
  .authorizeHttpRequests(auth -> auth.anyRequest().authenticated())
  .oauth2ResourceServer(oauth2 -> oauth2
    .jwt(jwt -> jwt.jwtAuthenticationConverter(myConverter())));

2Configurar issuer-uri o jwk-set-uri del Authorization Server
3Implementar JwtAuthenticationConverter para mapear claims a authorities
4Proteger endpoints con hasAuthority("SCOPE_read") o @PreAuthorize
