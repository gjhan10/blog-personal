Profiles

Configura comportamientos diferentes según el entorno usando Spring Profiles.

application-{{ '{' }}profile{{ '}' }}.yml
Crea application-dev.yml, application-prod.yml. Las propiedades sobrescriben application.yml.
Activar profile
spring.profiles.active=prod en properties, variable de entorno SPRING_PROFILES_ACTIVE=prod, o argumento JVM -Dspring.profiles.active=prod.
@Profile en beans
@Profile("dev") en una clase @Configuration o @Bean — sólo se carga cuando ese perfil está activo.
@ConditionalOnProperty
@ConditionalOnProperty(name="feature.x", havingValue="true") — activa beans según propiedades, independientemente del perfil.
# application.yml (base)
spring:
  profiles:
    active: dev
  config:
    import: optional:file:./config/extra.yml
spring.config.import (Spring Boot 2.4+) permite importar archivos de configuración adicionales, incluyendo Config Server o archivos locales.

Docker

Empaqueta tu aplicación Spring Boot en una imagen Docker optimizada con multi-stage build.

Multi-stage build
Fase 1: imagen Maven/JDK para compilar. Fase 2: imagen JRE slim solo con el jar. Resultado: imagen final ligera sin herramientas de build.
layertools
java -Djarmode=layertools -jar app.jar extract — divide el jar en capas (dependencies, spring-boot-loader, application) para mejor cache de Docker.
JVM Memory flags
-XX:MaxRAMPercentage=75.0 adapta el heap al contenedor automáticamente. Más fiable que -Xmx fijo en Kubernetes.
Distroless
Imagen gcr.io/distroless/java21 — sin shell, sin package manager. Mínima superficie de ataque. Alternativa segura a eclipse-temurin:21-jre-alpine.
# Dockerfile (multi-stage + layertools)
FROM eclipse-temurin:21-jdk-alpine AS builder
WORKDIR /app
COPY target/*.jar app.jar
RUN java -Djarmode=layertools -jar app.jar extract
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=builder /app/dependencies/ ./
COPY --from=builder /app/spring-boot-loader/ ./
COPY --from=builder /app/application/ ./
EXPOSE 8080
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75.0", "org.springframework.boot.loader.launch.JarLauncher"]

docker-compose

Orquesta múltiples contenedores (app + DB + cache) con docker compose.

compose.yml
Desde Docker Compose v2: el archivo se llama compose.yml (sin guión). El comando es docker compose (sin guión).
depends_on + healthcheck
depends_on: db: condition: service_healthy — espera a que el healthcheck del servicio db sea exitoso antes de arrancar el app.
Networks & Volumes
Red interna nombrada para que servicios se comuniquen por nombre. Volumen nombrado para persistir datos de PostgreSQL entre reinicios.
Override files
compose.override.yml se fusiona automáticamente. Útil para configs locales de dev sin modificar el archivo base.
services:
  app:
    build: .
    ports: ["8080:8080"]
    depends_on:
      db: {{ '{' }} condition: service_healthy {{ '}' }}
  db:
    image: postgres:16-alpine
    healthcheck:
      test: ["CMD","pg_isready","-U","postgres"]
      interval: 5s
      retries: 5

Kubernetes Basics

Despliega tu aplicación Spring Boot en Kubernetes con alta disponibilidad.

Deployment
Define replicas, imagen Docker, variables de entorno desde ConfigMap/Secret, y estrategia de update (RollingUpdate vs Recreate).
Probes
livenessProbe: /actuator/health/liveness. readinessProbe: /actuator/health/readiness. Configurar initialDelaySeconds apropiado.
HPA
HorizontalPodAutoscaler escala réplicas según CPU/memoria o métricas custom. Requiere metrics-server instalado en el cluster.
ConfigMap vs Secret
ConfigMap para configuración no sensible. Secret para passwords/tokens (base64 en etcd, no encriptado por defecto — usar Sealed Secrets o Vault).
livenessProbe:
  httpGet: {{ '{' }}path: /actuator/health/liveness, port: 8080 {{ '}' }}
  initialDelaySeconds: 30
  periodSeconds: 10
readinessProbe:
  httpGet: {{ '{' }}path: /actuator/health/readiness, port: 8080 {{ '}' }}
  initialDelaySeconds: 15
Liveness y Readiness son probes distintas — no uses la misma URL. Un fallo en liveness reinicia el pod; en readiness solo lo saca del servicio.

CI/CD con GitHub Actions

Automatiza build, test, push de imagen y despliegue con pipelines reproducibles.

Workflow triggers
on: push: branches: [main] o on: pull_request. Usa workflow_dispatch para ejecución manual.
Cache Maven/Gradle
actions/cache@v4 con path ~/.m2/repository y key basada en hash del pom.xml. Reduce tiempo de build significativamente.
Secrets
Guarda credentials en Settings → Secrets. Accede con ${{ '{{' }} secrets.DOCKER_PASSWORD {{ '}}' }} — sintaxis de expresión de GitHub Actions. Nunca hardcodees credenciales en el workflow.
Rolling update
kubectl set image deployment/app app=registry/app:$SHA. Kubernetes reemplaza pods gradualmente sin downtime.
jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: {{ '{' }}java-version: '21', distribution: 'temurin', cache: 'maven' {{ '}' }}
      - run: mvn verify
      - uses: docker/build-push-action@v5
        with: {{ '{' }}push: true, tags: app:{{ '${' + '{' }} github.sha {{ '}' + '}' }} {{ '}' }}
Usa mvn verify en lugar de mvn package para ejecutar los tests de integración también en el pipeline.
