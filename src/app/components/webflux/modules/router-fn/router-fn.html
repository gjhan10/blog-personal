Configurar Spring WebFlux

Setup del proyecto, dependencias, servidor Netty y configuración automática de Spring Boot.

??
Dependencia
spring-boot-starter-webflux incluye: Reactor Core, Reactor Netty, Spring WebFlux, Jackson. Excluye Tomcat y Spring MVC automáticamente.
?
Netty como servidor
Reactor Netty como servidor por defecto. No hay Servlet API. Puerto 8080 por defecto. Cambiable con server.port en application.properties.
??
WebFluxConfigurer
Implementar WebFluxConfigurer para personalizar: encoders/decoders, CORS, formatters, path matching. Anotación @EnableWebFlux desactiva la auto-config.
??
Spring MVC vs WebFlux
No pueden coexistir en el mismo proyecto. WebFlux en Netty: sin Servlet API, sin HttpServletRequest/Response. Usa ServerHttpRequest/ServerHttpResponse.
<!-- pom.xml -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>
// application.properties
server.port=8080
spring.webflux.base-path=/api
Si tienes spring-boot-starter-web y spring-boot-starter-webflux, Spring MVC ganará. Para WebFlux puro, usa solo webflux.

@RestController Reactivo

El estilo anotado conocido de Spring MVC, ahora con retornos reactivos Mono y Flux.

@RestController
@RequestMapping("/products")
public class ProductController {{ '{' }}
  @GetMapping
  public Flux<Product> all() {{ '{' }}
    return repo.findAll();  // Flux reactivo
  {{ '}' }}
  @GetMapping("/{{ '{' }}id{{ '}' }}")
  public Mono<ResponseEntity<Product>> byId(@PathVariable Long id) {{ '{' }}
    return repo.findById(id)
      .map(ResponseEntity::ok)
      .defaultIfEmpty(ResponseEntity.notFound().build());
  {{ '}' }}
  @PostMapping
  public Mono<ResponseEntity<Product>> create(@RequestBody Mono<Product> body) {{ '{' }}
    return body.flatMap(repo::save)
      .map(p -> ResponseEntity.created(uri(p.getId())).body(p));
  {{ '}' }}
{{ '}' }}
Puedes recibir @RequestBody Mono<T> para streaming de cuerpo reactivo, o el tipo directo @RequestBody T (WebFlux lo wrappea automáticamente).
18Módulo 3 · Router Functions

Router Functions

El modelo funcional de WebFlux: rutas como funciones puras sin anotaciones.

???
RouterFunction
Función que mapea ServerRequest ? Mono<HandlerFunction>. Creada con RouterFunctions.route() builder. Declarada como @Bean.
??
HandlerFunction
Función ServerRequest ? Mono<ServerResponse>. Es el "controlador" funcional. Normalmente agrupada en una clase Handler separada.
??
RequestPredicates
GET("/path"), POST("/path"), accept(APPLICATION_JSON), contentType(APPLICATION_JSON). Se combinan con .and(), .or().
???
ServerResponse builder
ServerResponse.ok().bodyValue(obj), .body(flux, Type.class), .build(). Status codes: .status(HttpStatus.CREATED).
@Configuration
public class ProductRouter {{ '{' }}
  @Bean
  public RouterFunction<ServerResponse> routes(ProductHandler h) {{ '{' }}
    return RouterFunctions.route()
      .GET("/products", h::findAll)
      .GET("/products/{{ '{' }}id{{ '}' }}", h::findById)
      .POST("/products", h::create)
      .build();
  {{ '}' }}
{{ '}' }}

Manejo de Errores Global

Captura y transformación de excepciones en endpoints reactivos.

??
@ExceptionHandler reactivo
En @ControllerAdvice: devuelve Mono<ResponseEntity>. Spring WebFlux lo soporta igual que MVC pero con tipos reactivos.
??
WebExceptionHandler
Interfaz de bajo nivel para Router Functions. Implementar y registrar como @Bean con @Order. Recibe ServerWebExchange.
??
DefaultErrorWebExceptionHandler
Clase base de Spring Boot para manejo de errores global. Extiéndela para personalizar el formato de respuesta de errores.
??
Problem Details (RFC 7807)
Spring 6/Boot 3: spring.mvc.problemdetails.enabled=true. Respuesta estándar: type, title, status, detail. Compatible con WebFlux.
@RestControllerAdvice
public class GlobalErrorHandler {{ '{' }}
  @ExceptionHandler(NotFoundException.class)
  public Mono<ResponseEntity<ErrorDTO>>
    handleNotFound(NotFoundException ex) {{ '{' }}
    return Mono.just(
      ResponseEntity.status(404)
        .body(new ErrorDTO(ex.getMessage())));
  {{ '}' }}

20Módulo 3 · Router Functions

Server-Sent Events (SSE)

Streaming de eventos del servidor al cliente usando text/event-stream con WebFlux.

??
¿Qu→ es SSE?
Protocolo HTTP unidireccional servidor ? cliente. La conexión permanece abierta. El cliente recibe eventos en tiempo real. Nativo en navegadores via EventSource API.
??
Flux<ServerSentEvent>
Retornar Flux<ServerSentEvent<T>> con media type text/event-stream. Cada SSE tiene id, event, data, retry opcionales.
??
Hot Flux con Sinks
Usar Sinks.many().multicast() como fuente compartida. El endpoint SSE suscribe al Flux del Sink. Los eventos de negocio se emiten al Sink desde cualquier parte.
??
Keepalive
Emitir un comentario (:) periódicamente para mantener la conexión activa. Usar Flux.interval() + mergeWith para combinar eventos reales con heartbeats.
@GetMapping(value = "/events",
      produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> stream() {{ '{' }}
  return Flux.interval(Duration.ofSeconds(1))
    .map(seq -> ServerSentEvent.<String>builder()
      .id(String.valueOf(seq))
      .event("message")
      .data("tick-" + seq)
      .build());
{{ '}' }}
