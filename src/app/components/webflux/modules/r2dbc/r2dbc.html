R2DBC vs JDBC

El driver de base de datos reactivo que sustituye a JDBC en aplicaciones WebFlux.

JDBC (bloqueante)
Hilo bloqueado durante la query ResultSet síncrono No compatible con Reactor Requiere boundedElastic wrapper No soporta backpressure
R2DBC (reactivo)
Retorna Mono/Flux directamente No bloquea ningún hilo Compatible con Netty event loop Backpressure end-to-end Drivers: H2, PostgreSQL, MySQL, MSSQL
Dependencia
spring-boot-starter-data-r2dbc + driver reactivo: io.r2dbc:r2dbc-postgresql o r2dbc-h2 para tests.
Connection Pool
R2DBC Pool (r2dbc-pool) gestiona conexiones. Configurable con spring.r2dbc.pool.initial-size, max-size. Mucho menor que pool JDBC.
ConnectionFactory
La abstracción central de R2DBC equivalente a DataSource. Auto-configurada por Spring Boot con spring.r2dbc.url.
Sin JPA
JPA/Hibernate no es compatible con R2DBC. Usa Spring Data R2DBC que proporciona repositorios reactivos pero sin lazy loading, cascades ni first-level cache de JPA.
# application.properties
spring.r2dbc.url=r2dbc:postgresql://localhost:5432/mydb
spring.r2dbc.username=user
spring.r2dbc.password=pass
spring.r2dbc.pool.max-size=20

ReactiveCrudRepository

La interfaz de repositorio reactivo de Spring Data R2DBC.

@Table("products")
public class Product {{ '{' }}
  @Id private Long id;
  private String name;
  private BigDecimal price;
{{ '}' }}
public interface ProductRepository
    extends ReactiveCrudRepository<Product, Long> {{ '{' }}
  Flux<Product> findByNameContaining(String name);
  Flux<Product> findByPriceLessThan(BigDecimal max);
  Mono<Product> findFirstByName(String name);
{{ '}' }}
Métodos heredados
save(entity) → Mono<T>, findById(id) → Mono<T>, findAll() → Flux<T>, deleteById(id) → Mono<Void>, count() → Mono<Long>.
ReactiveSortingRepository
Extiende ReactiveCrudRepository añadiendo findAll(Sort). Para paginación usa ReactivePagingAndSortingRepository con findAll(Pageable).
Las entidades R2DBC usan @Table, @Column, @Id de Spring Data (no JPA). No se anotan con @Entity.

Queries y @Query Reactivas

Consultas personalizadas con SQL nativo reactivo en Spring Data R2DBC.

@Query("SELECT * FROM products WHERE category = :cat ORDER BY price")
Flux<Product> findByCategoryOrdered(@Param("cat") String category);
@Modifying
@Query("UPDATE products SET price = :price WHERE id = :id")
Mono<Integer> updatePrice(@Param("id") Long id, @Param("price") BigDecimal price);
// R2dbcEntityTemplate para queries dinámicas
@Autowired R2dbcEntityTemplate template;
Flux<Product> search = template.select(Product.class)
  .matching(Query.query(Criteria.where("price").lessThan(maxPrice)))
  .all();
R2DBC usa SQL nativo (no JPQL). Las queries derivadas como findByNameAndPrice son generadas automáticamente por Spring Data, igual que en JPA.

Transacciones Reactivas

Gestión de transacciones en contexto reactivo con @Transactional y TransactionalOperator.

@Transactional reactivo
Spring propaga la transacción a través del contexto de Reactor (no ThreadLocal). Funciona automáticamente si el método retorna Mono/Flux y está anotado con @Transactional.
TransactionalOperator
Para transacciones programáticas. transactionalOperator.transactional(flux) o .execute(callback). Útil cuando @Transactional no es suficiente (conditional tx).
Contexto de Reactor
Spring usa Context de Reactor (no ThreadLocal) para propagar la transacción. No funciona si cambias el scheduler dentro de la transacción sin gestión especial.
Rollback reactivo
Si el Mono/Flux retornado completa con error, Spring hace rollback automáticamente (igual que en Spring MVC, pero el error debe propagarse reactivamente).
@Transactional
public Mono<Order> createOrder(OrderDTO dto) {{ '{' }}
  return inventoryRepo.decreaseStock(dto.productId(), dto.qty())
    .then(orderRepo.save(dto.toEntity())); // tx abarca ambas ops
{{ '}' }}
26Módulo 4 · R2DBC

Redis Reactivo con Lettuce

Acceso reactivo a Redis usando el driver Lettuce y ReactiveRedisTemplate.

Lettuce
Driver Redis asíncrono y reactivo. Es el driver por defecto de Spring Data Redis cuando se usa WebFlux. Usa Netty internamente para conexiones non-blocking.
ReactiveRedisTemplate
Template reactivo para operaciones Redis. Métodos: opsForValue() (strings), opsForHash(), opsForSet(), opsForList(), opsForZSet().
Caché reactiva
Patrón: redis.get(key).switchIfEmpty(db.query().flatMap(v -> redis.set(key,v).thenReturn(v))). Cache-aside reactivo sin bloquear.
Pub/Sub reactivo
ReactiveRedisMessageListenerContainer para suscribirse a canales Redis como Flux. Mensajes llegan como stream reactivo a los suscriptores.
ReactiveValueOperations<String,Product> ops =
  redisTemplate.opsForValue();
Mono<Product> getProduct(Long id) {{ '{' }}
  String key = "product:" + id;
  return ops.get(key)
    .switchIfEmpty(
      repo.findById(id)
        .flatMap(p -> ops.set(key, p, Duration.ofMinutes(10))
          .thenReturn(p)));
{{ '}' }}
