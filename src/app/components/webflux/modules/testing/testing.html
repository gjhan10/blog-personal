38Módulo 7 · Testing

StepVerifier Avanzado

Pruebas precisas de pipelines reactivos con tiempo virtual, secuencias y grabación.

withVirtualTime()
Permite simular el paso del tiempo sin esperar realmente. StepVerifier.withVirtualTime(() -> Flux.interval(Duration.ofSeconds(1))). El supplier es obligatorio para capturar la suscripción con VirtualTimeScheduler.
thenAwait(Duration)
Avanza el reloj virtual: .thenAwait(Duration.ofSeconds(10)). Después de avanzar el reloj, se pueden verificar los elementos emitidos. No hay espera real.
recordWith
.recordWith(ArrayList::new).thenConsumeWhile(x -> true).consumeRecordedWith(list -> assertThat(list).containsExactly(...)). Acumula elementos para assertions complejas.
expectNextCount
.expectNextCount(100) verifica que se emiten exactamente N elementos sin inspeccionarlos. Combina con .expectNextMatches(predicate) para elementos específicos.
// Test con tiempo virtual
StepVerifier.withVirtualTime(() ->
  Flux.interval(Duration.ofSeconds(1)).take(3))
  .expectSubscription()
  .thenAwait(Duration.ofSeconds(3))
  .expectNextCount(3)
  .verifyComplete();
// recordWith para assertions sobre la colección
StepVerifier.create(service.getAll())
  .recordWith(ArrayList::new)
  .thenConsumeWhile(p -> true)
  .consumeRecordedWith(list ->
    assertThat(list).hasSize(5))
  .verifyComplete();

WebTestClient

Cliente HTTP de pruebas para endpoints WebFlux: integración y unitaria.

bindToApplicationContext
Test de integración completo: WebTestClient.bindToApplicationContext(ctx).build(). Inicia el contexto de Spring completo sin servidor real. Opción: bindToServer("http://localhost:8080").
bindToRouterFunction
WebTestClient.bindToRouterFunction(routerFn).build(). Para testear Router Functions de forma aislada. Sin contexto de Spring completo — test unitario puro.
expectBody + jsonPath
.expectBody().jsonPath("$.name").isEqualTo("Alice"). Para objetos tipados: .expectBody(Product.class).value(p -> assertThat(p.name()).isEqualTo("X")).
expectBodyList
.expectBodyList(Product.class).hasSize(3).contains(product1). Para Flux: .returnResult(Product.class).getResponseBody() retorna un Flux para procesar con StepVerifier.

40Módulo 7 · Testing

@WebFluxTest y Mocking

Tests unitarios de controladores WebFlux con contexto reducido y mocks reactivos.

@WebFluxTest
Carga solo los beans de la capa web: controllers, HandlerFunctions, WebFilter. No carga services ni repositories. Auto-configura WebTestClient. Más rápido que @SpringBootTest.
@MockBean
Crea un mock de Mockito y lo registra en el contexto de Spring. Los mocks de servicios deben devolver Mono/Flux: when(service.find(1L)).thenReturn(Mono.just(product)).
Mono.empty() en mocks
Para simular 404: when(repo.findById(99L)).thenReturn(Mono.empty()). El controlador debería hacer .switchIfEmpty(Mono.error(new NotFoundException())).
mutateWith para seguridad
webTestClient.mutateWith(mockJwt().jwt(j -> j.subject("user1"))).get().... O mutateWith(csrf()) para endpoints con CSRF. Evita configurar tokens reales en tests.
@WebFluxTest(ProductController.class)
class ProductControllerTest {{ '{' }}
  @Autowired WebTestClient client;
  @MockBean ProductService service;
  @Test
  void returns404WhenNotFound() {{ '{' }}
    when(service.findById(99L)).thenReturn(Mono.empty());
    client.get().uri("/products/99")
      .exchange()
      .expectStatus().isNotFound();
  {{ '}' }}
