Chain of Responsibility

Evita acoplar el emisor de una solicitud a su receptor al encadenar objetos receptores. Cada handler decide si procesa la solicitud o la pasa al siguiente en la cadena.

Intención
Cada handler tiene una referencia al siguiente. Procesa si puede, si no, delega. El cliente solo conoce el primer handler de la cadena.
Java — Filtros de Log
Cadena de filtros de nivel: Debug → Info → Warning → Error. Cada filtro procesa mensajes de su nivel y los pasa hacia arriba si el nivel es mayor.
Cuándo usarlo
Cadenas de aprobación (gastos), pipelines de middleware, filtros de seguridad donde el conjunto y orden de handlers puede variar.
Cuidado
Si ningún handler procesa la solicitud, puede perderse silenciosamente. Siempre tener un handler final por defecto que maneje el caso no atendido.

Command

Encapsula una solicitud como un objeto, permitiendo parametrizar clientes con diferentes solicitudes, soportar deshacer/rehacer, y colas de operaciones.

Encapsulación de acción
La acción se convierte en objeto con método execute(). El Invoker no sabe qué hace el comando, solo lo ejecuta. Permite encolamiento, logging y deshacer.
Undo/Redo
Añadir undo() al Command y mantener un historial (stack). Para deshacer: recorrer el stack hacia atrás llamando undo(). Para rehacer: redo(). Editores de texto, operaciones de DB.
Java — Transacciones
Cada operación de DB es un Command con execute() y rollback(). TransactionManager mantiene el historial. Si falla, recorre la lista llamando rollback() en orden inverso.
Cuándo usarlo
Operaciones que requieren deshacer/rehacer, colas de tareas asíncronas, logging de operaciones para auditoría o recuperación ante fallos.

Iterator

Proporciona una forma de acceder secuencialmente a los elementos de una colección sin exponer su implementación interna. Separa el recorrido de la estructura de datos.

Interfaz Iterator
hasNext(): boolean, next(): T, remove(). El cliente usa la interfaz sin conocer si es un array, lista enlazada, árbol o cualquier estructura de datos.
Java — Iterable
Implementar Iterable<T> con iterator() permite usar el for-each de Java. Las colecciones de Java (List, Set, Queue) todas implementan Iterable. El patrón está en el JDK.
Tree Iterator
Un árbol puede tener iteradores con diferentes estrategias: inorder, preorder, postorder, BFS. El cliente usa la misma interfaz independientemente del recorrido elegido.
ConcurrentModification
En Java, modificar la colección durante la iteración lanza ConcurrentModificationException. Usar Iterator.remove() si es necesario eliminar durante el recorrido.

Mediator

Define un objeto que encapsula cómo interactúan un conjunto de objetos. Reduce las dependencias directas entre clases al hacer que se comuniquen a través del mediador.

Problema
Sin mediador: N componentes con N×(N-1)/2 conexiones. Con mediador: N componentes, cada uno solo conoce al mediador. Menos acoplamiento, más mantenible.
Torre de control
Los aviones (componentes) no se comunican entre sí directamente. Todos hablan con la torre de control (mediador) que coordina el tráfico aéreo.
Java — Event Bus
Un EventBus (Guava, Spring ApplicationEventPublisher) actúa como mediador. Los componentes publican eventos y se suscriben a tipos de eventos sin conocerse entre sí.
God Object
El Mediator puede convertirse en un God Object si acumula demasiada lógica. Mantenerlo como coordinador puro sin lógica de negocio. La lógica pertenece a los componentes.

Memento

Permite capturar y externalizar el estado interno de un objeto sin violar su encapsulación, para poder restaurarlo posteriormente (undo/redo, snapshots).

Tres roles
Originator: el objeto cuyo estado se guarda. Memento: el snapshot del estado (opaco al Caretaker). Caretaker: gestiona el historial de Mementos sin acceder a su contenido.
Undo/Redo
Originator crea Memento (save state), Caretaker guarda en stack. Para deshacer: Caretaker devuelve el Memento al Originator que restaura su estado. El estado nunca se expone.
Java — Serialización
El estado se puede serializar a bytes/JSON como Memento. Para restaurar, deserializar. Útil para persistir checkpoints de aplicación o implementar autosave.
Memoria
Guardar muchos snapshots puede consumir mucha memoria. Estrategias: límite en el historial, snapshots incrementales (solo el delta), o compresión del estado.

Observer

Define una dependencia uno-a-muchos entre objetos. Cuando el Subject cambia de estado, todos los observadores son notificados automáticamente. Fundamento de los sistemas reactivos.

Publish-Subscribe
El Subject no sabe quiénes son sus observadores ni cuántos hay. Solo llama update() en todos. Los observers se registran y desregistran dinámicamente.
Java — PropertyChangeListener
java.beans.PropertyChangeListener es el Observer estándar de Java. Spring usa ApplicationListener. Reactive: java.util.concurrent.Flow (RxJava, Project Reactor).
Cuándo usarlo
Sistemas de eventos (GUI), notificaciones en tiempo real, sincronización de estado entre vistas, cualquier situación donde múltiples objetos dependen del estado de otro.
Memory Leaks
Olvidar deregistrar observers crea memory leaks (el Subject mantiene referencias). Usar WeakReference para observers o siempre hacer unsubscribe en el ciclo de vida.

  public void subscribe(Observer<T> o) {{ '{' }} observers.add(o); {{ '}' }}
  public void publish(T event) {{ '{' }} observers.forEach(o -> o.update(event)); {{ '}' }}

State

Permite que un objeto altere su comportamiento cuando su estado interno cambia. El objeto parecerá que cambia de clase. Elimina los condicionales de estado con polimorfismo.

vs Strategy
Strategy: el cliente elige el algoritmo explícitamente. State: el objeto cambia de estado (y comportamiento) automáticamente según las transiciones internas. El Context gestiona el estado actual.
Java — enum State Machine
Los enums en Java pueden tener métodos. Cada constante implementa el comportamiento de su estado. Transiciones definidas por métodos del enum. Alternativa idiomática al State clásico.
Cuándo usarlo
Máquinas de estado finito: pedidos (PENDING→CONFIRMED→SHIPPED→DELIVERED), conexiones (CONNECTING→CONNECTED→DISCONNECTED), semáforos, vending machines.
Beneficio
Elimina grandes bloques if-else o switch por estado. Agregar un nuevo estado = añadir una clase/constante, sin modificar las existentes (Open/Closed Principle).

Strategy

Define una familia de algoritmos, los encapsula y los hace intercambiables. El cliente puede seleccionar el algoritmo en tiempo de ejecución sin cambiar el código que lo usa.

Eliminación de condicionales
Reemplaza switch/if-else de tipo de algoritmo con polimorfismo. Cada Strategy es una clase con su implementación. Agregar un nuevo algoritmo = nueva clase, sin modificar el Context.
Java 8+ — Lambdas
Si la Strategy es una interfaz funcional (@FunctionalInterface), puede implementarse con lambdas. Comparator.comparing() en streams usa Strategy. Muy idiomático en Java moderno.
Ejemplo — Pagos
PaymentStrategy con implementaciones: CreditCardPayment, PayPalPayment, CryptoPayment. El Checkout usa PaymentStrategy sin conocer el método concreto. Se configura en runtime.
Cuándo usarlo
Múltiples algoritmos de ordenamiento/compresión/cifrado, métodos de pago, estrategias de validación, estrategias de log, cualquier familia de algoritmos intercambiables.

Template Method

Define el esqueleto de un algoritmo en la clase base, dejando que las subclases implementen los pasos variables. Evita duplicación del flujo manteniendo variabilidad en los detalles.

Pasos fijos vs variables
El método template en la clase base llama pasos en orden. Pasos fijos: implementados en la base (final). Pasos variables: abstract o con implementación por defecto (hook methods).
Java — JdbcTemplate
Spring JdbcTemplate es Template Method en acción. El template gestiona obtener conexión, ejecutar y limpiar. Tú defines la query y el ResultSet mapper. Flujo fijo, comportamiento variable.
Preparación de bebidas
El algoritmo: hervir agua, preparar bebida, servir, añadir condimentos. El Template define el orden. Las subclases (Té, Café) implementan "preparar bebida" y "añadir condimentos".
vs Strategy
Template Method usa herencia (subclase extiende). Strategy usa composición (objeto delega a strategy). Template Method viola Open/Closed menos fácilmente que Strategy. Preferir Strategy en diseño moderno.

Visitor

Permite agregar nuevas operaciones a una jerarquía de clases sin modificarlas. El Visitor implementa Double Dispatch: el elemento acepta al Visitor que invoca la operación correcta.

Double Dispatch
Element.accept(visitor) llama visitor.visit(this). El tipo de visitor determina la operación; el tipo de elemento determina la sobrecarga. Ambos participan en la selección del método.
Java — AST Visitors
Compiladores y parsers (JavaParser, ANTLR, ByteBuddy) usan Visitor para recorrer el AST. Cada nodo acepta al Visitor que puede hacer análisis, transformación o generación de código.
Ejemplo — Reporte fiscal
Elementos: Libro, Electrónico, Alimento. Visitor: FiscalReportVisitor con visit(Book), visit(Electronic), visit(Food). Cada tipo tiene IVA diferente. Nueva operación = nuevo Visitor, sin tocar los elementos.
Desventaja
Si se añade un nuevo tipo de elemento, hay que modificar todos los Visitors. Adecuado cuando la jerarquía de elementos es estable pero las operaciones cambian frecuentemente.

Interpreter

Dado un lenguaje, define una representación de su gramática junto con un intérprete que usa dicha representación para interpretar sentencias del lenguaje.

Cuándo usarlo
Para lenguajes de consulta simples, expresiones regulares, motores de reglas de negocio, DSLs, parsers de expresiones matemáticas o de configuración.
Java — SpEL
Spring Expression Language (SpEL) es un Interpreter. También java.util.regex.Pattern, javax.el en JSF, y motores de reglas como Drools implementan este patrón a gran escala.
Abstract Syntax Tree
La gramática se representa como un árbol. Las expresiones terminales son nodos hoja; las no terminales son nodos internos. Evaluar = recorrer el árbol llamando interpret() en cada nodo.
Complejidad
Para gramáticas complejas, el número de clases crece rápidamente. Preferir herramientas como ANTLR o PEG para gramáticas no triviales. Interpreter es adecuado para lenguajes pequeños y simples.
