13OOP

Constructores

El constructor inicializa el objeto en el momento de su creación. Tiene el mismo nombre que la clase, sin tipo de retorno. Puede haber múltiples constructores (sobrecarga).

Si no se define ningún constructor, Java proporciona uno por defecto sin parámetros. En cuanto defines uno con parámetros, el de defecto desaparece.

Miembros estáticos (static)

Un miembro static (atributo o método) pertenece a la clase, no a los objetos. Se carga en memoria una sola vez y se comparte entre todas las instancias. En otras palabras: los miembros estáticos son "de la clase", no "del objeto".

Variables estáticas

  • Se declaran con la palabra clave static.
  • Son compartidas por todos los objetos de la clase.
  • Útiles para contadores, configuraciones globales o constantes.
Clase Persona
class Persona {{ '{' }}
  static int contador = 0; // compartida
  String nombre;
  Persona(String n) {{ '{' }}
    nombre = n;
    contador++; // crece con cada objeto
  {{ '}' }}
{{ '}' }}
Acceso en main
new Persona("Ana");
new Persona("Luis");
System.out.println(Persona.contador); // 2

Métodos estáticos

  • Pertenecen a la clase, no necesitan crear un objeto para usarse.
  • Solo pueden acceder a otros miembros estáticos (no a variables de instancia).

Abstracción

Mecanismo que oculta los detalles de implementación y expone únicamente lo esencial. Se logra con clases abstractas e interfaces.

  • Oculta los detalles y muestra solo lo necesario.
  • Es el proceso de definir qué hace un objeto sin mostrar cómo lo hace.
  • Permite trabajar a un nivel conceptual, sin preocuparse por la implementación.
  • Se usa para simplificar sistemas complejos dividiéndolos en modelos más simples.
  • Se logra con clases abstractas o interfaces.

17OOP

Herencia

extends permite que una clase hija herede campos y métodos de la clase padre. Java solo soporta herencia simple. super accede al padre.

  • Una clase puede heredar atributos y métodos de otra.
  • Se usa la palabra clave extends.
  • A la clase "padre" se le conoce como superclase, mientras que la "hija" es la subclase.
El método sobreescrito debe tener exactamente la misma firma. Anota siempre @Override para que el compilador lo verifique.

Consideraciones

  • Todas las clases heredan de Object.
  • Si una clase no hereda explícitamente de otra, implícitamente hereda de Object.
  • Una clase sólo puede heredar otra clase, aunque la superclase puede heredar a su vez a otra y así hasta n niveles.
  • Varias clases pueden heredar la misma clase.
  • Los miembros private de la superclase no son accesibles directamente desde la subclase.
  • Si queremos que una clase no se pueda heredar, la definiremos con final.
  • Entre la subclase y la superclase hay una relación de tipo "Es un".
  • Un objeto de la subclase "es un" objeto del tipo de la superclase.

Polimorfismo

Un objeto puede tomar muchas formas. Con polimorfismo de tiempo de ejecución (dynamic dispatch), un array de Animal puede contener objetos Perro y Gato y llamar al método correcto de cada uno.

  • Significa "muchas formas".
  • Capacidad de un objeto de tomar diferentes formas y permitir que un mismo método se comporte de distintas maneras según el tipo real del objeto que lo ejecute.
  • Funciona mediante herencia e interfaces.
Ejemplo — polimorfismo con herencia
class Animal {{ '{' }} void sonido() {{ '{' }} System.out.println("Sonido de animal"); {{ '}' }} {{ '}' }}
class Perro extends Animal {{ '{' }} void sonido() {{ '{' }} System.out.println("Guau!"); {{ '}' }} {{ '}' }}
class Gato extends Animal {{ '{' }} void sonido() {{ '{' }} System.out.println("Miau!"); {{ '}' }} {{ '}' }}

Animal a = new Perro();
a.sonido(); // Guau!

30OOP

Interfaces

Una interfaz en Java es un tipo de referencia que define un conjunto de métodos abstractos (sin implementación) que una clase debe implementar.

También puede contener constantes, métodos por defecto (default) y métodos estáticos.

  • Definir contratos que las clases deben cumplir
  • Aplicar polimorfismo
  • Separar el "qué" del "cómo"
  • Simular herencia múltiple
  • Crear código más flexible y mantenible
  • Usadas ampliamente en APIs, frameworks, eventos, inyección de dependencias, etc.

Interfaces Funcionales

  • Una interfaz funcional es una interfaz que tiene exactamente un solo método abstracto. Ese método define la "función" principal que la interfaz representa.
  • Estas interfaces se usan principalmente para trabajar con expresiones lambda y la programación funcional introducida en Java 8.
  • Tiene un solo método abstracto (obligatorio), este método define la operación principal.
  • Puede tener métodos default y static, no afectan la condición de que sea funcional.
  • Puede llevar la anotación @FunctionalInterface, esto no es obligatorio, pero:
    • Garantiza que la interfaz cumple la regla del método único.
    • Produce error de compilación si se agregan métodos extra.
  • Es compatible automáticamente con expresiones lambda.

Ejemplo:

Interfaz funcional con lambda
Operacion suma = (a, b) -> a + b;

Permite implementar comportamientos de manera concisa, especialmente en streams, callbacks y programación reactiva.

Enumeraciones

Una enumeración (enum) en Java es un tipo especial de clase que representa un conjunto fijo y limitado de valores constantes.

Por ejemplo, los días de la semana, los colores de un semáforo, los estados de un pedido, etc.

Los enums se introdujeron en Java 5 y permiten definir constantes de una forma más segura y organizada que las clásicas static final.

Ejemplo — enum EstadoPedido con atributo
public enum EstadoPedido {{ '{' }}
  PENDIENTE("El pedido está pendiente"),
  EN_PROCESO("El pedido está en proceso"),
  ENVIADO("El pedido fue enviado"),
  ENTREGADO("El pedido fue entregado");

  private String descripcion;

Clases Abstractas

Una clase abstracta no puede instanciarse directamente y puede contener métodos abstractos (sin implementación) y métodos concretos (con implementación). Se utiliza para definir una estructura común que deben seguir las clases hijas.

Ejemplo — abstract class Animal
abstract class Animal {{ '{' }}

  abstract void sonido(); // sin implementación

  void dormir() {{ '{' }} // método concreto
    System.out.println("El animal está durmiendo");
  {{ '}' }}
{{ '}' }}

Características

  • No es posible crear objetos de una clase abstracta.
  • Además de métodos abstractos, las clases abstractas pueden incluir atributos, constructores y métodos estándares.
  • Una clase que herede una clase abstracta está obligada a sobrescribir los métodos abstractos heredados (o declararse también como abstract).
  • El objetivo de los métodos abstractos es forzar a que todas las subclases tengan el mismo formato de método.
  • Puede haber clases abstractas sin ningún método abstracto.
Instanciación y polimorfismo
// Animal a = new Animal();  ❌ ERROR — no se puede instanciar

Animal p = new Perro(); // ✓ uso de polimorfismo
p.hacerSonido();
p.dormir();
No puedes hacer new Animal() si es abstracta. Debes crear una subclase concreta.
