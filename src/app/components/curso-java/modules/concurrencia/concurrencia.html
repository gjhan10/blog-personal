41Concurrencia

Threads & Runnable

Un Thread es una unidad de ejecución. Para crear uno: extiende Thread o implementa Runnable (preferido). start() lanza el hilo; run() solo ejecuta en el hilo actual.

Desde Java 8 puedes usar lambdas: new Thread(() -> System.out.println("Hilo")).start();
42Concurrencia

Sincronización

synchronized garantiza que solo un hilo accede al bloque a la vez. Evita condiciones de carrera (race conditions). Alternativas modernas: ReentrantLock, AtomicInteger.

La sincronización excesiva causa deadlock. Prefiere java.util.concurrent.atomic para contadores simples.
43Concurrencia

ExecutorService & Thread Pools

ExecutorService gestiona un pool de hilos reutilizables. Evita crear/destruir hilos manualmente. submit() retorna un Future con el resultado.

FactoryDescripción
newFixedThreadPool(n)Pool de n hilos fijos
newCachedThreadPool()Pool dinámico, reutiliza ociosos
newSingleThreadExecutor()Un solo hilo secuencial
newScheduledThreadPool(n)Tareas programadas / periódicas
44Concurrencia

CompletableFuture (Java 8+)

Permite programación asíncrona y no bloqueante con encadenamiento funcional. thenApply, thenCombine, thenCompose, exceptionally.

¿Cuáles son las 4 condiciones necesarias para que ocurra un deadlock?
A

B

C
Concurrencia, sincronización, memoria compartida, bloqueo
